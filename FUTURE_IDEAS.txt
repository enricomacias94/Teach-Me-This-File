Teach Me This File — future ideas (unlimited resources)
=======================================================

Ideas below are NOT in the app yet. They are notes for later if
we have time and budget. Current product still works without them.

Time = rough build effort for one developer familiar with this repo.
Cost = extra money beyond normal coding time (APIs, infra, tools).
USD estimates assume light student use; real cost scales with traffic.


1) Drag and drop PDF
--------------------
What:
  Let the teacher drop a PDF onto the prepare screen instead of
  (or in addition to) clicking "choose file".

Why:
  Faster and more natural when preparing many lessons.

Notes:
  Same limits as today (PDF, max size). Only UX change; APIs stay
  the same.

Time: about 0.5–1 day
Cost: ~$0 (no new services)


2) Read handwritten / scanned PDFs
----------------------------------
What:
  Support PDFs that are photos or scans of handwriting, not typed
  digital text.

Why:
  Many school worksheets and student notes are handwritten.

How (high level):
  - OCR and/or a vision model to turn page images into text
  - Keep the current text path for normal digital PDFs
  - Show confidence / warn when handwriting is unclear

Notes:
  This changes requirements: more cost, latency, and possible
  mistakes on math symbols. Needs a clear product decision.

Time: about 1–2 weeks (OCR + vision path + UX warnings + tests)
Cost:
  - OCR/vision APIs: roughly $0.01–$0.05+ per page (provider-dependent)
  - Example: 20-page handwritten worksheet ≈ $0.20–$1.00 per upload
  - Plus higher OpenAI tutoring tokens if extracted text is noisy/long


3) Save session results + grading / progress tracking
-----------------------------------------------------
What:
  Store each student lesson session after it ends:
  - which PDF / course
  - steps completed
  - answers given
  - tutor judgments (advance / hints)
  - a simple grade or score per step and per session

Why:
  Teachers (and students) can see evolution over time:
  stronger topics, repeated mistakes, improvement across sessions.

Ideas for grading:
  - per step: pass / fail or 0–100 based on attempts and hints
  - per session: average or weighted score
  - history chart: scores across dates for the same subject/PDF

Notes:
  Needs persistence (database or accounts). Today everything is
  in-memory and is lost on refresh. Saving sessions is a bigger
  product step (accounts, privacy, storage).

Time: about 1–3 weeks (auth optional, DB, history UI, grading rules)
Cost:
  - Hosting/DB: often $0–$25/month early (free tiers possible)
  - Little extra OpenAI cost if we only store what we already call
  - If we add “re-grade with AI” later: more tokens per session


4) Token usage panel (efficiency / cost control)
------------------------------------------------
What:
  Track OpenAI token usage for each interaction, for example:
  - /api/lesson (build plan)
  - /api/tutor open / reply / evaluation
  - prompt tokens, completion tokens, total
  - optional estimated cost

  Show this in an internal window or panel (not required for the
  student UI). Server logs alone are enough for a first version.

Why:
  Control and manage efficiency: see which steps burn tokens,
  compare models, avoid wasteful prompts.

How (high level):
  - Read `usage` from OpenAI responses (including end-of-stream
    usage when streaming)
  - Store per-call records in memory or a simple log file
  - Later: small internal "Usage" panel with totals per session

Notes:
  Does not change the student lesson flow. Start with server-side
  logging; add a UI panel only if useful for teachers/admins.

Time:
  - Logging only: about 0.5–1 day
  - Internal usage panel: about 2–4 extra days
Cost: ~$0 extra services (uses data we already pay for via OpenAI)


Priority suggestion (if we build later)
---------------------------------------
  A. Drag and drop — small, safe (~0.5–1 day, ~$0)
  B. Token usage logging / internal panel — small–medium, high control value
  C. Save sessions + simple grading — high teaching value (weeks + hosting)
  D. Handwritten PDF reading — powerful but heavier (weeks + per-page API $)
